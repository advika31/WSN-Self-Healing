# Recovery policy v2: transient faults, blackholes, and constrained paths

## Frozen question and design

**Primary endpoint:** per-seed PDR difference for `diagnosis_aware` minus `blind_reroute`, analyzed by paired 95% t interval across 30 seeds. This tests the incremental value of diagnosis over rerouting without diagnoses. The project does not call a result publishable based on direction alone. The diagnosis-aware versus permanent generic exclusion contrast is secondary and exploratory.

The experiment crosses two graph structures (`sparse`, `bottleneck`) with two relay fault loads (20% and 40%). There are ten relay candidates; the intended number of faulty relays is two or four. Relay 16 is deliberately the faulty articulation relay in every seed. Relays 10 and 15 are fixed branch-end blackholes so their removal does not itself eliminate every route in the sparse condition. Ten sensor sources each offer two packets per round for 60 rounds. Seeds are 201–230. Node telemetry is generated by the current challenging-mode simulator and each node's predictions are out-of-fold: the Random Forest fold holding that node out produces all of its round predictions. The fault label's simulator telemetry remains intermittent even though its node-level class is fixed.

The sparse graph has multiple low-degree routes and can bypass relay 16. In the bottleneck graph, every route from the sensor tier to the gateway passes through relay 16. Therefore, excluding any suspected node can strand demands in that condition. This is intentionally a bottleneck stress test; it is not a random deployment topology.

## Recovery strategies

- **Blind reroute:** does not use diagnoses; allows all live nodes, retries up to three times, then avoids a failed edge for the current packet and searches another path.
- **Generic permanent exclusion:** permanently excludes any relay once it is predicted fault or blackhole. It does not distinguish a transient fault from an attack.
- **Diagnosis-aware:** permanently isolates each relay predicted as a blackhole and records one alert per node. A fault prediction quarantines that relay for at least two rounds; two consecutive normal predictions are also required before readmission. Re-admitted fault relays receive a modeled transmit-power boost. If a fault is diagnosed again after readmission, a maintenance flag is counted.

Blackhole false negatives are not removed using ground-truth labels: they can remain on a route and drop packets at the model's blackhole forwarding probability. Thus the alert/isolation action is diagnosis-driven, and a missed blackhole remains a possible failure. A fault node's observed simulator PDR at or below 0.80 marks that round's low-PDR transient state for packet forwarding. This reuses the simulator's challenging-mode low-PDR branch (nominally selected 55% of fault readings), so its telemetry is aligned with the transient forwarding state rather than generated independently. All policies use identical per-packet directed link uniforms, fault-state readings, topology, offered traffic, and battery starting states within each seed-condition.

## Metric definitions

- **PDR:** delivered offered packets divided by all offered packets over the 60-round run.
- **Delay:** `2 + 0.1 × edge distance` model milliseconds for every transmission attempt, averaged over offered packets. It is not measured latency.
- **Energy:** abstract units per attempt: transmit `(1 + 0.002 × distance²)` and receive `0.5`; re-admitted transmit-power adjustment multiplies transmit cost by 1.25. Values are not joules.
- **Battery/network lifetime:** all nodes start with 1,000 abstract energy units. First-node-death is the first round when any node reaches zero. The service lifetime proxy is the first of three consecutive rounds with PDR below 0.50. If the event does not occur by round 60, the output is 61 and must be read as right-censored (`>60`), not as an observed lifetime. This is a deliberately simple model, not battery calibration.
- **Recovery time:** rounds between the most recent fault prediction and re-admission after the quarantine/normal-streak requirements. It measures policy timing, not repair time in a physical network.
- **Route availability:** fraction of offered packets for which the live, policy-eligible graph had a path before transmission.
- **Alerts and maintenance:** unique relays permanently classified as blackholes and repeat fault flags after readmission, respectively.
- **Classifier metrics:** per-seed precision, recall, and F1 for normal, fault, and blackhole classes, plus accuracy. Confidence intervals are calculated across seeds; the 1,200 within-seed node-round rows are not treated as independent replicates.

Energy and lifetime are model proxies. The directed radio model, failure process, energy constants, fixed graph, and classifier telemetry are synthetic and uncalibrated. The model has no MAC contention, queueing, control-plane overhead, mobility, hardware measurements, or independent WSN-DS/Intel data. It tests whether the action rules differ under declared conditions; it cannot predict field performance. Keep these outputs separate from the existing v3 packet and sensitivity estimates.

## Run

From the repository root in PowerShell:

```powershell
python -m unittest discover -s tests -v
python -m experiments.recovery_policy_v2
```

Outputs are newly written to `results/recovery_policy_v2/`: `per_seed_metrics.csv`, `paired_comparisons.csv`, `classification_per_seed.csv`, `classification_summary_ci.csv`, and `summary.csv`. Reproduction includes 30 seeds; do not report early partial outputs as full results.
